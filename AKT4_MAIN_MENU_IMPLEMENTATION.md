# AKT4 Main Menu — Implementation Plan

Status: **Plan only — not implemented**  
Target scene: `Assets/Scenes/Aktivity/akt4/akt4.unity`  
Reference: supplied “AKTIVITI 4” image, 16:9 layout

## 1. Objective

Rebuild only the `Canvas/Center` landing menu so it closely matches the supplied cheerful science-themed reference while preserving all current AKT4 navigation and lesson content.

The redesign will keep the reference's main visual hierarchy:

- Warm yellow/lime/orange background with soft science decorations.
- Large cream title plaque with dark-green `AKTIVITI 4` text.
- Four wide rounded menu bars with white borders and shadows.
- Left icon medallions and large centered labels.
- Bottom curriculum card: `SP: 3.1` and `SK: 3.1.1, 3.1.3`.
- Water-drop character on the lower left.
- Purple microbe, microscope, and petri dish on the lower right.
- Existing Home navigation retained in a small corner control.

## 2. Current Scene Findings

- Unity: `6000.4.5f1`; active scene is already `akt4.unity`.
- Existing UI is uGUI with TextMeshPro and the Input System.
- Canvas scaler already uses `1920 × 1080`, Scale With Screen Size.
- Existing menu hierarchy:
  - `Canvas/Center/Title`
  - `Canvas/Center/GameObject`
  - `Button (1)` → `PENGENALAN`
  - `Button (2)` → `FAKTOR`
  - `Button (3)` → `MICRO-SCENE`
  - `Button (4)` → `KUIZ`
  - `HomeButton`
- Existing lesson panels (`Pengenalan`, `Faktor`, `MicroLab`, `Kuiz`, etc.), video players, `SceneController`, and `EventSystem` will not be rebuilt.
- Existing font is `Assets/Fonts/FredokaOne SDF.asset`, which suits the reference.

## 5. Visual Specifications

Base layout uses the existing `1920 × 1080` reference resolution.

- Title plaque: approximately `900 × 150`, upper-center, cream fill, green edge, soft offset shadow.
- Title: dark green, Fredoka One, approximately `92–104 pt`, centered.
- Menu stack: approximately `930–960 px` wide, centered slightly above mid-screen.
- Buttons: approximately `920 × 126`, about `18–22 px` vertical spacing.
- Menu colors:
  - Pengenalan: purple (`#A743D5` family)
  - Faktor: blue (`#2478E5` family)
  - Micro-Scene: lime green (`#67C900` family)
  - Kuiz: orange (`#FF9300` family)
- Button labels: white, Fredoka One, approximately `52–58 pt`, subtle dark colored shadow/outline.
- Icon medallions: approximately `150 × 126`, overlapping the left edge of each bar.
- Curriculum card: cream rounded card, lower center, dark-green text around `31–36 pt`.
- Character art must stay outside button hit areas and use `raycastTarget = false`.
- Home button remains easy to reach but visually secondary, at the lower-left safe margin.
- All primary controls use anchors so the composition remains stable across 16:9 and modestly wider/narrower screens.

## 6. Functionality Preservation

- Keep the five legacy source buttons serialized in the scene.
- Hide the old `Title` and old `GameObject` visuals after the replacement root is ready.
- Connect each generated button to its corresponding original button through the existing `CenterMenuButtonRelay` component.
- Preserve mappings exactly:
  - Pengenalan → legacy `Button (1)`
  - Faktor → legacy `Button (2)`
  - Micro-Scene → legacy `Button (3)`
  - Kuiz → legacy `Button (4)`
  - Home → legacy `HomeButton`
- Do not change destination panels, video players, scene names, or controller code.
- Disable automatic Selectable navigation on generated buttons to avoid unexpected keyboard/gamepad jumps unless current testing shows it is required.

## 7. Implementation Method

Use the same project convention already established by the Activity 5/6/7/8 center-menu builders.

1. Create `Assets/Editor/Akt4CenterMenuUIBuilder.cs` through Unity MCP.
2. The editor builder will:
   - Verify the active scene and required assets.
   - Create a one-time backup at `Assets/Scenes/Aktivity/akt4/Backups/akt4_PreCenterMenuRedesign_20260904.unity`.
   - Generate/import the dedicated gradient background if it does not exist.
   - Delete only a previous `Akt4CenterRedesignRoot`, making reruns idempotent.
   - Build the complete new hierarchy in one editor operation.
   - Add relay components and preserve all legacy button actions.
   - Hide the legacy center visuals.
   - Save the target scene.
3. Execute the builder through Unity MCP after compilation succeeds.

This editor-builder route is more efficient and reproducible than dozens of individual scene edits. Unity MCP will still be used for creation, execution, and verification.

## 8. Unity MCP Execution Sequence

When implementation is approved:

1. Read `mcpforunity://editor/state` and confirm the editor is idle.
2. Read the target objects once by instance ID/path.
3. Create the editor builder in one script operation.
4. Wait for compilation; read only error logs.
5. Execute the builder once.
6. Run one batched verification containing:
   - New root lookup.
   - Generated-button lookup.
   - Required component checks.
   - Scene hierarchy validation.
7. Capture one `1920 × 1080` Game View screenshot.
8. If needed, perform one grouped correction pass, then capture one final screenshot.
9. Enter Play Mode once and smoke-test all five buttons.
10. Exit Play Mode, check errors once, and save.

Round-trip policy:

- Use `batch_execute` for independent lookups/component checks.
- Maximum one hierarchy audit before and one after the build.
- Maximum one console check after compilation and one after Play Mode.
- No repeated refreshes; script creation already triggers import/compilation.
- Screenshots capped to the resolution needed for visual comparison.
